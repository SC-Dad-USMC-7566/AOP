The Architecture of Persistence (AOP) — Canon (v1.0 designation)

WHAT THIS DOCUMENT IS. This is the canon *designation* for AOP — a short governing document that
names what the canon is, fixes which version is canonical right now, and states the rules for how
canon is read and changed. It deliberately does **not** restate AOP's claims. Restating them here
would fork the truth into two documents; the whole point of having a canon is that there is exactly
one source. So this document points, and the thing it points at *is* the canon.

---

**The canon is the paper.** AOP's canon is the manuscript *The Architecture of Persistence*
(a Perspective, written to standalone journal standard). Every AOP claim lives there and only
there: the four dimensions (Boundary, Drive, Memory, Integration) and their formal definitions as
relative entropies; the two layers (syntactic coupling graph + semantic mask); the coupling
classification and its status tags; the three load-bearing refusals; the five worked cases; the
domain and its edge; the limitations; and the reference list. If you want to know what AOP claims,
read the paper. If it is not in the paper, it is not yet canon.

**Current canonical version.** As of this designation, the canonical version is **v1.4**
(file: aop_v1_4.md / aop_v1_4.html). v1.4 is claim-hardened: every reference verified against
primary sources (one econometrics citation still to be finalized, flagged in-text and load-bearing
on nothing), the three previously-open couplings closed against the literature, and the
persistence-selection grounding added. Its companion documents:
- *Changelog* (aop_v1_4_changelog.md) — what changed from the prior version and why.
- *Reference audit* (aop_reference_audit.md) — the per-reference verification record.
- *Claim assessment* (aop_claim_assessment.md) — the pressure-test of the load-bearing claims.
- *Gap results* (aop_gap1/2/3_*.md) — the three computational studies that closed the open couplings.
- *AOP → Ladder bridge memo* (aop_ladder_bridge_memo.md) — canon-adjacent, Ladder-facing; maps AOP
  onto the eleven rungs. Kept separate from the paper so the paper stays standalone.

**What is canon, and what is not.**
- *Canon:* the current version of the paper, in full, including its claim-status tags. A claim's
  strength is part of the canon — "settled," "this framework's synthesis," and "frontier" are not
  decoration; a frontier claim is canon *as a frontier claim*, not as settled fact.
- *Not canon:* the charter (governance, not claims); the changelog, audit, and gap-result documents
  (they *support* the canon and record how it was built, but the paper is what is claimed); anything
  in a retired framework (BIH, PIC, TPL); and any claim that exists only in conversation and has not
  been written into a version of the paper.

**How canon changes.** Canon changes only by a new version of the paper, and only when the science
changes — a claim is added, cut, re-graded, or re-scoped, and a reference is verified to support it.
The bar is the paper's own evidence standard: don't create when you can cite; verify against primary
sources; be skeptical of anything that looks new; grade the claim. When a new version supersedes
this one, update the "current canonical version" line above and post the change to the cross-project
handoff bus if it affects The Ladder. Old versions are retained (they are the record), but only one
version is canonical at a time.

**The relationship to the charter.** The charter says *how we work* and points here for *what is
true*. This canon says *what is true* (by pointing at the paper) and never mentions how the project
is run. Neither document restates the other. If a proposed edit to one is really content that
belongs in the other, it goes in the other. That separation is what keeps the charter loose and the
canon rigid — each doing its own job.
