## Tool notes

**The single most important operational finding of this session:**

> **The Drive connector cannot place certified artefacts. This is structural, not a size limit to wait out.** `create_file` exposes no path or URL parameter — content enters only as `textContent` or `base64Content`, both model-generated strings. A 255 KB artefact is ~253,000 characters (~70–79k output tokens; base64 ~114k) and exceeds the output ceiling. **Even with no ceiling, routing bytes through token generation cannot guarantee byte-exactness:** the canon carries 556 em-dashes, 151 en-dashes, 27 minus signs, 217 `§`, a combining dot-above (U+0307), curly quotes and primes. One character of drift breaks the md5, and what lands is a *reconstruction*, not the certified artefact. Write permission is **not** the blocker (`canAddChildren: true`); Drive accepts 255 KB trivially.
>
> **Byte-exact placement through the connector tops out in the low tens of KB and is never guaranteed at any size.** Paths that move actual bytes: manual upload by Ben, `device_commit_files` into a Drive-synced folder, or a resumable Drive upload from a shell with credentials. The **verification** half — metadata `fileSize` plus `download_file_content` → md5 — is sound and was never the problem.

If asked to attempt a large placement anyway: **stop rather than push through.** Completing it forces either a truncated file in the canon folder under the certified name, or generation past the point where the content is in context, which is fabrication. Prime declined this on 4 August and CW reached the same conclusion independently.

Other notes:

- Large Drive downloads land at `/mnt/user-data/tool_results/*.json`. Decode: `json.loads(d[0]['text'])` → `base64.b64decode(inner['content'])` → write to `/home/claude/` → hash.
- `create_file` works for ~20–30 KB with `textContent` + `disableConversionToGoogleType: true` + `contentMimeType: text/markdown`. Confirm by comparing returned `fileSize` to local byte count, then queue hash verification to CW.
- **Seats do not share filesystems.** CW's `/home/claude` is a different machine from prime's. A file certified in one seat is not reachable from another; it must move through Drive or through Ben.
- `read_file_content` returns empty for some markdown written with conversion disabled — fall back to `download_file_content`.
- Folder listing: `parentId = '[id]'` with `excludeContentSnippets=True`. Paginate; the first page is not the whole folder.
- `fullText contains` loose-matches badly. Never an existence test inside a large document.
- Line counts: `str.split("\n")`, not `wc -l`.
- **Google-Docs-native copies are a live hazard.** Conversion drops `---` rules, escapes bold/italic to literal text, restructures tables, loses code spans, and corrupts escape sequences (`str.split("\n")` → `str.split("\\n")`). A converted twin can never hash to a stamp. Always check `mimeType`, not just title.
