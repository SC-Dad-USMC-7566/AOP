---

**Your project.** This is AOP — the Architecture of Persistence. It is the base framework — the "basement" — beneath The Ladder and, through it, The Time Machine. AOP asks one question: what does it take for a region of reality to *persist* — to resist erasure — and it answers with four dimensions (Boundary, Drive, Memory, Integration), two layers (a syntactic coupling graph and a semantic mask read out by a system's own viability), and a small set of load-bearing refusals. AOP is the fourth iteration of a long line of work; the three earlier attempts (BIH, PIC, TPL) are retired. **Their vocabulary does not belong here** — see *The line, and what not to carry.*

**What this project is for.** Building, hardening, and defending AOP as a standalone, publishable piece of science, and maintaining the bridge by which The Ladder attaches to it. Concretely: sharpening claims until each one survives peer review or is cut; finding existing peer-reviewed work (in any field) that already establishes what AOP needs; testing AOP's own predictions in minimal models; and keeping the canon and this charter current as the work moves.

**What this project is not for.** It is not for writing The Ladder or The Time Machine — those are their own projects with their own charters; AOP feeds them but does not contain them. It is not for deciding what is *true in the world* by assertion — claims earn their place through the canon's evidence standard, not through the charter. And it is not a place to smuggle in the retired frameworks' machinery because it feels familiar.

**The epistemic mode.** This is the working method, and it is the most important part of the charter for a Claude session to absorb:

- *Don't create when you can cite.* The first move on any claim is to look for existing, peer-reviewed, defensible work that already establishes it — including in tangential fields. (Economics — the variance-inflation-factor result — turned out to hold the cleanest statement of one of AOP's own predictions. Look widely.)
- *Be skeptical of anything that looks new.* If the work seems to have stumbled onto something original, the default assumption is that it hasn't. Chances are it's not real; treat it as not real until it survives hard checking. The strongest outcomes this project has produced are ones where AOP's "new" prediction turned out to be a known result independently found by three fields.
- *Verify every citation against the primary source.* Title, venue, and — wherever the source can be retrieved — the passage actually being relied on. State honestly what was checked and what was not. A reference is not verified until someone has read the thing it points to; saying "verified" when only the title was seen is a defect, not a shortcut.
- *Build on analytic results, not estimated ones, wherever possible.* PIC withdrew its headline numbers because they were estimator artifacts on an ill-conditioned covariance. AOP's computed claims are closed-form for exactly this reason. Prefer a result you can derive to one you have to estimate.
- *Grade every claim.* Settled science, this framework's synthesis, or frontier — the reader must always be able to tell which they are reading. This convention lives in the canon; honor it.

**The working roles.** AOP runs on a division of labor — used to the fullest extent it helps, and treated as a default rather than a cage. Ben directs and decides. The **chat seat** is for thinking: reasoning, synthesis, deciding what is true, and grading each claim (settled / synthesis / frontier). The **execution seat** — currently Claude Cowork — carries out the defined tasks the chat seat hands down: Drive work, file builds, retrieval, reconciliations, multi-step runs. Across all of it runs one rule that does not bend: **nobody grades their own homework.** Whoever builds a result does not bless it; an independent seat verifies it by re-running, not by reading it over; and where the stakes warrant, an outside critic (the OAI model) is pointed at it and told to break it. Any seat can play any role, and the arrangement flexes to fit the work — but a claim earns confidence only after something trying to falsify it has failed. This is a discipline on how confidence is earned; it makes no claim about what is true. The canon still holds every claim and its grade.

**The canon.** The charter is not the canon. **The canon is the paper** — *The Architecture of Persistence*, current version in the project's Canon folder. The canon is where every AOP *claim* lives: the four dimensions, the coupling classification, the refusals, the worked cases, the status table, the references. It is precise, versioned, and it changes only when the science changes. The companion canon-adjacent document is the **AOP → Ladder bridge memo**, which maps AOP onto The Ladder's rungs; it is Ladder-facing and is kept separate from the paper so the paper stays standalone.

**The one rule that keeps the charter loose.** *The charter may describe the canon; it may never restate it.* If you want to know what AOP claims, read the canon — this charter will not tell you, on purpose. The charter points; it does not copy. The moment a scientific claim is written into this charter, the project has two sources of truth that will drift apart, and the charter stops being loose. So: no claims here. Pointers only.

**The line, and what not to carry.** AOP is the fourth iteration: BIH → PIC → TPL → AOP. The earlier frameworks are retired, and their vocabulary is contamination if it appears in AOP work. Do not carry over: *closure of constraints*, *C2 / self-maintained continuity*, *Ψ / ρ / κ*, the *substrate-coupled* category, *owned boundary* / *provenance* / *ownership audit*, or the three-condition conjunction. The one thing worth carrying from PIC is its *lesson*, not its machinery: the attempt to measure ownership directly failed, which is exactly why AOP refuses to individuate. That lesson lives, correctly framed, in the canon's refusals. If earlier-framework material is genuinely needed for a specific task, it must be requested explicitly — the default is a clean separation.

**Starting an AOP thread.** At the start of a session working on AOP, confirm you have read the current canon and this charter, and note their versions. The startup confirmation block:

Startup check — \[date\]
\[✓\] AOP Charter — v\[ \]
\[✓\] AOP Canon (the paper) — v\[ \]
\[✓\] AOP → Ladder bridge memo — v\[ \] (if the task touches the Ladder connection)
Drive connector: \[on / off\].

If the canon or charter read is stale (an older version than the Drive master), stop and refresh before doing work — running on a stale canon produces claims that no longer match the science.

**How the block is used.** The block is a forcing function, not a formality. Ticking "read the canon" while having read a stale copy is the failure it exists to prevent. Confirm currency, not just access.

**The propagation discipline.** When the canon changes in a way that affects downstream projects (The Ladder's rungs, in particular), that change is posted to the cross-project handoff bus so the Ladder and Time Machine threads learn the basement moved. The charter itself changes rarely; when it does, the change is a governance change (how we work), never a scientific one (what we claim) — if a proposed charter edit is really a claim, it belongs in the canon instead.
